# 网格数据说明（NTv2 `.gsb`）

初审意见里有一条：**「请明确……所需变换数据」**。这份文档就是那个答案。

一句话结论：**本库实现的是算法，不随附数据。** 要拿到米级以下的跨基准精度，必须
自备官方网格文件；文件从哪来、什么许可、怎么确认它盖住了你的作业区，下面逐条写清。

---

## 1. 为什么数据不进仓库

两个理由，都不是"懒"：

1. **许可**。OSTN15 由英国地形测量局（Ordnance Survey）发布，NADCON 由美国 NOAA/NGS
   发布，各国测绘部门的网格普遍带"可自由使用、不可再分发"或"需注册后下载"的条款。
   把它们放进 Apache-2.0 仓库，等于给下游用户埋一个许可地雷。
2. **体积**。全国级网格常见几 MB 到几十 MB，仓库会以每周一次的频率变大。

所以边界划在这里：**算法在仓库里，数据在调用方手里**。`grid` 包只接受字节，
不认识路径；读文件只发生在 CLI 的 `--grid` 参数上。

---

## 2. 已登记的网格类运算

| 运算 | 网格标识（`--grid` 用的名字） | 官方文件 | 发布方 | 许可 | 状态 |
| --- | --- | --- | --- | --- | --- |
| `EPSG:7709` OSGB36 → ETRS89 | `OSTN15_NTv2_OSGBtoETRS` | `OSTN15_NTv2_OSGBtoETRS.gsb` | Ordnance Survey（英国） | 按 OS OpenData / OGL 发布，具体以官方页面为准 | **可执行**（提供文件即可） |
| `EPSG:1241` NAD27 → NAD83 | `conus` | `conus.las` / `conus.los` | NOAA / NGS（美国） | 美国政府作品，公有领域 | **格式未实现**：NADCON 是 `.las/.los`，本版只解析 NTv2 |

"网格标识"是注册表里的键，也是 `--grid` 的默认 ID（取文件名去扩展名）。所以

```bash
mooncrs transform --grid OSTN15_NTv2_OSGBtoETRS.gsb EPSG:4277 EPSG:4258 1.7179 52.6576
```

不需要再写一遍 ID。文件名不一样时用 `--grid ID=路径` 显式指定：

```bash
mooncrs transform --grid OSTN15_NTv2_OSGBtoETRS=/data/uk/osgb15.gsb EPSG:4277 EPSG:4258 ...
```

## 3. 格式支持的确切边界

`grid` 包实现的是 NTv2（Geomatics Canada, 1996）。以下是**会明确报错**而不是
"读进来算错"的情形：

| 情形 | 行为 |
| --- | --- |
| 大端字节序文件 | 报错：只读小端，请先转换 |
| `GS_TYPE = MINUTES` / `DEGREES` | 报错：只支持 `SECONDS` |
| `VERSION` 非 `NTv2`（如 NTv1 的 `.dat`） | 报错：布局不同 |
| 文件头/子文件头标签错位 | 报错：指出第几条记录的标签是什么、期望什么 |
| `GS_COUNT` 与范围×格距算出的节点数不符 | 报错：两个数字都打出来 |
| 节点数据被截断 | 报错：需要读到第几字节、文件只有多少字节 |
| 点落在所有子网格之外 | 报错并给出覆盖范围；**不外推** |
| 同一文件内子网格的经度约定互相矛盾 | 报错，不猜 |

两处约定值得单独说明，因为它们是 NTv2 里最容易搞反的地方：

- **经度是"正西"**。文件里 `E_LONG` / `W_LONG` 都是正的角秒数，表示西经。
  本库先用这个约定读，再用 `east > west` 自洽条件反证；若只有"正东"读法自洽，
  就判为正东文件并把结论写进 `lon_convention`，同时输出到 `grid` 子命令里。
- **节点从东南角开始，先向西再向北**。写成先向东会得到一张左右镜像的网格，
  数值看着仍然"连续"，却整体错位——这类错误靠闭环测试查不出来（正反两次都错，
  闭环照样通过），只能靠约定本身正确。

## 4. 怎么确认网格盖住了作业区

拿到文件先别急着转换，跑一次摘要：

```bash
mooncrs grid OSTN15_NTv2_OSGBtoETRS.gsb
```

输出里有子网格清单、格距、各自的范围与外接矩形。想直接看某点的改正量：

```bash
mooncrs grid OSTN15_NTv2_OSGBtoETRS.gsb -1.5 54.3
# → 纬改正 …″  经改正 …″  子网格 …
```

这在实务上有用：等到转换时报"点不在范围内"，往往已经跑完一批数据了。

## 5. 可复现校验：用真实网格对官方期望值

算法对不对，不能靠自己跟自己对。这里用 PROJ 项目自带的**真实 NTv2 文件**
（加拿大 NAD27→NAD83 的降采样版）与 PROJ 测试套件里的**期望输出**做对照。

- 文件：`https://raw.githubusercontent.com/OSGeo/PROJ/master/data/tests/ntv2_0_downsampled.gsb`
  （245 824 字节，7 个子网格；PROJ 仓库 MIT/X11，数据来自加拿大自然资源部）
- 期望值：`https://raw.githubusercontent.com/OSGeo/PROJ/master/test/cli/test_cs2cs_ntv2.yaml`
- 该文件**只用于校验，不随仓库分发**。

复现命令（`js` 目标即可，不依赖 MSVC）：

```bash
curl -LO https://raw.githubusercontent.com/OSGeo/PROJ/master/data/tests/ntv2_0_downsampled.gsb
moon run cmd/main --target js -- grid ./ntv2_0_downsampled.gsb -82 42
```

实测输出：

```

版本    NTv2.0（经度约定 west-positive）
椭球    源 a=6378206.4 b=6356583.8；目标 a=6378137 b=6356752.314
子网格  7 个
  CAeast  24 行 × 52 列，格距 3012.4999999999995″ × 3051.9230769230767″，…
  …
  ONwinsor  61 行 × 171 列，格距 30″ × 30″，ONwinsor [41.916666666666664, -83.16666666666667] .. [42.416666666666664, -81.75]
  …
覆盖    [40.376736111111114, -141.619140625] .. [83.5875, -44.38221153846155]
-82 42 → 纬改正 0.1601999998092652″  经改正 0.38962998986244207″  子网格 ONwinsor
```

PROJ 在 `test_cs2cs_ntv2.yaml` 里对同一个点的期望输出是

```
82d00'00.000"W 42d00'00.000"N  →  81d59'59.6104"W  42d0'0.1602"N
```

即经差 **+0.3896″**、纬差 **+0.1602″**，与本库算出的 `0.38963″ / 0.16020″` 一致
（差 3×10⁻⁵ 角秒，来自显示的舍入位数）。

边界点（`-115.58333333 51.25`，ALbanff 子网格）本库给出纬 +0.07669″、经 −3.77374″；
PROJ 的逆解（NAD83 → NAD27）得到 `-115.58228512 51.24997866`，反推经差 −3.7736″、
纬差 +0.0768″，两者相差 2×10⁻⁴ 角秒（约 6 mm）——这是两点相距 0.001° 造成的，
不是算法差异。

**这条校验证明的是"解析 + 插值"对了，不是"你的数据对了"。** 后者取决于你手上
那份官方文件，本库无从判断。

## 6. 精度怎么理解

- 网格类运算的精度写在注册表的 `accuracy_m` 里（OSTN15 标 0.1 m，NADCON 标 0.15 m），
  那是**发布方声明的精度**，不是本库算出来的。
- 本库不做"平均误差补偿"之类的小动作。节点值原样使用，双线性插值，不外推。
- 网格只改正平面坐标，高程不变。

## 7. 已知限制

| 限制 | 说明 |
| --- | --- |
| 只支持 NTv2 | NADCON（`.las/.los`）、GeoTIFF 网格（PROJ 7+ 的默认格式）尚未实现；相关运算会明确报"格式未实现"，不会伪装成"缺数据" |
| 只支持小端 + SECONDS | 大端、`MINUTES`、`DEGREES` 会报错并说明原因 |
| 网格不覆盖时不降级 | 不会自动改用低精度参数；报错并给出覆盖范围。静默降级会把"数据不够"伪装成"算完了" |
| 子网格切换 | 正向取"覆盖该点的最小子网格"。PROJ 在反解迭代中允许切换到母网格（`test_cs2cs_ntv2.yaml` 第 3 个用例即此情形），本库不复制该行为——那会让"同一个点在正反两个方向上用到不同的网格"，无法解释 |
| 网格数据需自备 | 见本文第 1 节 |
